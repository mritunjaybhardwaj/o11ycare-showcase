THE ORIGIN

It starts with an ordinary application log.

Applications write to stdout or stderr. Kubernetes captures those records in container log files on the node; the application does not need to call the dispatcher directly.

Metrics follow a separate path: Vector internal metrics and kube-state-metrics → Mimir → Grafana.

THE RESULT, WITHOUT THE FINE-PRINT SURPRISE

One specific failure.
One verifiable outcome.

✓ What this run proved

  • All 10,000 expected log IDs were found in Loki.
  • No missing records or API-observed duplicates.
  • The generator completed and the dispatcher was restored.

↗ What remains to validate

  • Full-buffer propagation and disk-full behavior.
  • Long outages and recovery across pod or node loss.
  • Multi-tenant data isolation and performance under contention.

Buffer occupancy was observed, not asserted. This test does not establish exactly-once delivery or a universal no-loss guarantee.

03 / ENGINEERING JUDGMENT

The decisions behind the flow.

Built to understand the failure modes—not just connect the components.

01

Bound the work.

A channel-based admission limiter caps concurrent dispatcher requests. When capacity is exhausted, it returns 429 so upstream can retry.

Concurrency ≠ request rate
02

Share clients, not request state.

One Go HTTP client and transport reuse downstream connections. Payloads, outgoing requests, and responses remain local to each handler invocation.

Reuse with clear ownership
03

Make recovery measurable.

A Go test runner uses Kubernetes and Loki APIs to coordinate the outage, restore replicas, and compare expected sequence IDs with delivered records.

Evidence over assumptions
04

Scale the bottleneck.

The next design step is to connect backlog growth with resource saturation and downstream health. More replicas help capacity; tenant fairness needs additional controls.

Design direction · not automated

04 / HONEST SCOPE

A working foundation.
A deliberate next step.

o11ycare is a POC, not a claim of production readiness. The roadmap separates data isolation from performance isolation.
